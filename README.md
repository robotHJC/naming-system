# 取名系统 · 五行八字

一个**纯前端、零依赖、打开即用**的中文取名系统。不用 Python、不用 npm、不用构建，
双击 `namingTools.bat` 或直接双击 `web/index.html` 就能跑。
字库与诗词库可在界面里**联网扩充**，也能**打包成单文件**拷到任何电脑上离线使用。

> 起名结果仅供参考。五行、数理、重名热度都存在流派差异与数据局限，
> 系统会明确标注哪些是推算、哪些是估算、哪些是推断，不假装精确。

---

## 快速开始

```
双击  namingTools.bat          # 用默认浏览器打开
```

或者直接双击 `web/index.html`，两种方式完全等价。

打开后有两个视图：

- **取名** —— 填条件出名字
- **词库管理** —— 联网扩充词库（见下文）

也可以带参数直接出结果：

```
web/index.html?surname=李&gender=女&style=古风&birth=2024-05-20T10:00&auto=1
```

| 参数 | 说明 |
| --- | --- |
| `surname` | 姓氏（支持复姓，如 `欧阳`） |
| `gender` | `男` / `女` / `中性` |
| `style` | `古风` `文雅` `大气` `温柔` `灵动` `简约` `自然` `清冷` |
| `birth` | 出生时间，`YYYY-MM-DDTHH:MM` |
| `auto` | `1` 表示加载后自动开始取名 |

## 打包发布（移植到其他电脑）

```
双击  打包.bat
```

产出 `dist/` 下三样东西：

| 产物 | 大小（内置字库） | 说明 |
| --- | --- | --- |
| `取名系统.html` | ≈ 320 KB | **单文件版**：CSS/JS/数据全部内联，拷一个文件过去双击就能用 |
| `取名系统-完整版/` | ≈ 334 KB | **文件夹版**：保留可编辑源码，方便改字库、加诗词 |
| `取名系统.zip` | ≈ 124 KB | 上面那个文件夹的压缩包，直接发给别人 |

目标电脑**不需要装任何东西**（不需要 Node、不需要 Python、不需要联网）。

### 想把已联网的词库一起打包？

先在「词库管理」里点**导出数据文件**，把导出的 JSON 放进 `tools/`，
再运行打包，数据就会**固化**进单文件里 —— 别人拿到即是「词库已扩充」状态，
不必重新下载那 26MB 的字典。

```bash
node tools/build-dist.js --bake tools/naming-lexicon-2026-09-18.json
node tools/build-dist.js --no-dict      # 固化但不含字典（文件更小）
node tools/build-dist.js --no-zip       # 跳过压缩包
node tools/build-dist.js                # 自动在 tools/ data/ 里找导出文件
```

| 五行强弱 | 天干 + **地支藏干加权**（本气 1.0 / 中气 0.5 / 余气 0.3）+ **月令加成**，按同党/异党力量比判身强身弱 |

| 同音替换 | 嫌某个字被用滥了，推荐读音相同、五行一致、更冷门的替换字（含词库外的字，标注推断） |

| 四川话检测 | 用蜀拼字表把名字转成四川话读音，检出方言里难听或撞词的名字（**仅提示**） |

| 联网扩充词库 | 拉取公开的拼音表 / 新华字典 / 诗词库 / 繁简对照表 / 蜀拼表，缓存到本地 |
| 单字联网查询 | 字库外的字可联网查出拼音、部首、笔画、释义，校正后加入字库 |
| 导出 | 一键复制文本结果 / 打印或存为 PDF / 导出词库数据文件 |

## 联网更新词库

在「词库管理」里勾选数据源，点「开始联网更新」。数据缓存在浏览器本地，
**更新一次之后离线也能用**。

### 数据源

| 分组 | 源 | 体积 | 默认 | 作用 |
| --- | --- | --- | --- | --- |
| 核心 | 繁简对照表（OpenCC） | 82 KB | ✅ | 繁体诗篇归一化 |
| 核心 | 汉字拼音表（2 万余字） | 821 KB | ✅ | 给字库外的字补拼音声调 |
| 诗词 | 诗经 / 楚辞 / 论语 | 330 KB | ✅ | 出处 |
| 诗词 | 唐诗三百首 / 千家诗 | 213 KB | ✅ | 出处 |
| 诗词 | 水墨唐诗 / 纳兰词 / 幽梦影 / 声律启蒙 / 增广贤文 / 千字文 / 幼学琼林 / 古文观止 | 1.4 MB | ⬜ | 出处 |
| 诗词 | 宋词（第一卷 · 约千首） | 397 KB | ⬜ | 出处 |
| 方言 | 蜀拼字表（1.3 万字四川话读音） | 403 KB | ⬜ | 四川话谐音检测 |
| 方言 | 四川方言词汇表（186 条） | 131 KB | ⬜ | 「听着像某个方言词」提示 |
| 字典 | 新华字典（1.6 万字） | 26 MB | ⬜ | 部首/简体笔画/释义 |

字典较大，首次下载实测约 1 分钟；其余全部加起来不到 2 MB，十几秒即可。

两个方言源**默认不勾选**，因为其来源仓库**未声明授权**，也不建议进入对外分发的包。

### 为什么不需要后端

所有数据源都返回 `Access-Control-Allow-Origin: *`，并且实测 `file://` 页面
可以直接 `fetch` 它们（Chrome 对 `null` 源放行通配符）。所以联网做在纯前端里，
没有任何服务端依赖 —— 这也是单文件版依然能联网的原因。

用 `node tools/probe-sources.js` 可以随时体检各数据源的可达性与 CORS 情况。

### ⚠️ 康熙笔画与五行：没有权威公开数据源

这一点必须说清楚。**拼音、部首、释义、诗词都有公开数据源可直接采用**，
但**「康熙笔画」与「姓名学五行」不存在可用的开放数据集**
（已在 GitHub 上核查过，只有零星无关结果）。

因此联网加进来的字只能**推断**：

- **五行**：按「部首派」映射（氵→水、木→木、钅→金、日→火、土→土……），
  标注置信度（各派一致 / 有分歧）
- **康熙笔画**：简体笔画 + 偏旁修正（艹 +3、氵 +1、讠 +5 …），标注为估算

界面上这些字会显示**「含推断字」红色徽标**，查询卡片里也会写明依据，
并要求人工核对后才能加入字库。**请勿当作权威数理结果。**

另外「整体简化」的字（铄→鑠、庆→慶）连偏旁修正也救不回来，
误差可能有好几画 —— 说明文字里会明确提示。

## 小名与地域

### 小名（每个结果附带一个）

小名**不重新生成**，而是从已选中的大名里衍生 —— 大名已经过了字义与五行筛选，
小名只要好叫、亲切、无谐音就够了。

候选 = 大名的每个用字 × 五种构词法：

| 构词 | 例 | 常见度权重 |
| --- | --- | --- |
| 叠字 | 涵涵 | 最高 |
| 小 + 字 | 小满 | 高 |
| 阿 + 字 | 阿宝 | 中 |
| 字 + 儿 | 可儿 | 中低 |
| 单字 | 霖 | 低（名字字本身够亲切时才优先） |

评分时会扣分或淘汰的情形：普通话谐音（**淘汰**）、与姓氏连读谐音（扣分）、
四川话撞词（扣分）、用字偏硬（如铁、锋、帝，叠叫容易被笑）。

### 地域：出生城市

内置 234 个城市经纬度，选城市后自动填经度，不必再手查。
经度影响**真太阳时**（每差 1° = 4 分钟），进而影响时柱与日柱。

选了四川/重庆会自动提示可开启四川话检测。

### 四川话谐音检测

**为什么不能只查普通话**：四川话有一系列系统性读音归并，会造出普通话里不存在的谐音 ——

| 归并 | 后果 |
| --- | --- |
| 前后鼻音不分 | 金=京、心=星、陈=程、兰=郎 |
| n/l 部分相混 | 林=凌、冷读 len |
| 入声单独标注 | 德、逸、黑、绿 记为第 5 声 |

实现方式：蜀拼字表给出每个字的四川话读音 → 名字转成读音序列 →
与负面词库的读音序列比对（词库用**汉字**书写，运行时再转读音，避免手写读音出错）。

实测能检出的真实例子（都是字库内的用字，确实会出现在结果里）：

| 名字 | 四川话 | 撞上 |
| --- | --- | --- |
| 柏岱 | be5 dai4 | 白带 |
| 枫梓 | fong1 zi3 | 疯子 |
| 梅蕴 | mei2 yun4 | 霉运 |
| 若智 | ro5 zhi4 | 弱智 |
| 茉德 | mo5 de5 | 莫得 |
| 范统 | fan4 tong3 | 饭桶 |

**只提示、不淘汰**，原因有两个：
1. 数据来源（shupin）未声明授权，且个别读音与成都话实际有出入
   （例如「闪」标为 shan2，成都话应为上声）
2. 四川话内部差异大（成渝片 / 岷江片读音不同），无法一概而论

## 关键设计取舍

### 1. 谐音检测：为什么必须带声调

原始的 `naming_system.py` 用「拼音子串包含」判断谐音，会把名字误杀得很惨：

| 名字 | 原版判定 | 原因 |
| --- | --- | --- |
| 李诗涵 | ❌ 淘汰 | 全拼 `lishihan` 里含子串 `shi` |
| 李枫林 | ❌ 淘汰 | 含 `feng`（黑名单里有） |
| 林灿 | ❌ 淘汰 | 含 `can`（黑名单里有） |

新版改成「按音节边界 + 比对声调」：

| 名字 | 新版判定 | 原因 |
| --- | --- | --- |
| 范统 `fan4-tong3` | ✅ 拦截 | 与「饭桶」声调完全一致 |
| 范彤 `fan4-tong2` | ✅ 放行 | 声调不同，不构成谐音 |
| 李思琪 `si1-qi2` | ✅ 放行 | 「死气」是 `si3-qi4`，声调不同 |
| 杨威 `yang2-wei1` | ✅ 放行 | 「阳痿」是 `yang2-wei3` |
| 杜子腾 `du4-zi3-teng2` | ✅ 拦截 | 「肚子疼」的「子」是轻声，作通配 |
| 若智 `ruo4-zhi4` | ✅ 拦截 | 与「弱智」同调 |

规则：**声调相符比例 = 1 时判定为谐音**；三字以上且 ≥0.6 时只提示。
另外「无语」「沉默」「孤独」这类轻度负面词归入**提示级**，只警告不淘汰。
声调未知（如手工填的拼音）与轻声（第 5 声）都按通配处理。

### 2. 节气：不用近似日期表

原版用「每月固定 6/4/6/5… 号」的近似表判断节气。本版用
**Meeus《Astronomical Algorithms》第 25 章**的低精度太阳视黄经公式
（含中心差、光行差 -0.00569°、章动主项 -0.00478°·sinΩ），
牛顿迭代求节气时刻。实测与公开天文年历对比：

| 节气 | 本系统 | 天文年历 | 误差 |
| --- | --- | --- | --- |
| 2024 立春 | 16:21 | 16:26 | 5 分 |
| 2024 清明 | 14:56 | 15:02 | 6 分 |
| 2024 大雪 | 23:15 | 23:17 | 2 分 |
| 2023 立春 | 10:34 | 10:42 | 8 分 |
| 2000 立春 | 20:37 | 20:40 | 3 分 |

八字换柱只关心「出生时刻在节气前还是后」，分钟级误差足够；
但如果出生时间恰好落在节气前后 10 分钟内，建议核对专业排盘软件。

### 3. 生成：先剪枝再枚举

原版对全部用字跑 `itertools.product`：双字名约 6.8 万组合，
**三字名超过 1700 万，会直接卡死**。

本版两阶段处理：

1. **剪枝**：五行、性别、风格、关键词这几项都是「逐字相加后再封顶」，
   所以单字基础分高的字一定更容易组合出高分名字——剪枝方向与最终排序一致。
   双字名保留 100 字，三字名保留 42 字。
2. **分块枚举**：每帧最多占用 24ms，剩下的交给下一个 `setTimeout`，
   界面全程可交互，并显示进度。

实测（本机 Node / Chromium）：

| 场景 | 枚举规模 | 耗时 |
| --- | --- | --- |
| 李 + 双字名（候选池 100） | 9,900 组 | ~110 ms |
| 王 + 三字名（候选池 42） | 68,880 组 | ~750 ms |
| 同上，但诗词库已扩充到 850 首 | 9,900 组 | ~118 ms |

最后一行是刻意回归的：诗词库从 35 首涨到 850 首后，
如果查找算法写得不小心（每个组合都去扫全部诗篇），耗时会明显上升。
这里的做法是**先按「诗篇列表最短」的那个字求交集**，再对参与字排序后的组合做
记忆化，所以扩充诗词库基本不影响生成速度。

关键词命中的字和「必含字」会被强制放进候选池，
不会因为单字分不够而被剪掉。

### 4. 排序：为什么结果不是严格按分数降序

**问题**：完全按分数取前 N，一个字只要分高就会霸占所有位置。
实测「李」+ 双字名的默认参数，修之前前 10 名是：

```
书云  书亦  书凌  书叶  书和  书园  书寒  书平  书忆  书文
```

10 个结果全部以「书」开头 —— 这是一个字 + 十种搭配，不是一个候选集合。

**做法**：加「同位不重字」约束。按分数从高到低扫描，限制同一个字在**同一个位置**
出现的次数，上限从 1 开始逐级放宽（1 → 2 → 3 → 5）；位次用尽后再放宽，
保证在多样性这一维度上饱和之后才出现重字。

修后同一组参数：`李若水 李碧秋 李秋碧 李水若 李安白 李贝琛` —— 首字全不重复。

实测对照（李 + 女 + 双字名，取前 8）：

| | 首字去重 | 最低分 |
| --- | --- | --- |
| 不约束 | 5 / 8 | — |
| 约束后 | **8 / 8** | 只比全局最高分低 10 分 |

**代价**：名次靠前的分数不再严格递减。这是有意的取舍 ——
取名工具的价值在于给出多样、可挑的候选，而不是把某个字的十种搭配排成一列。

### 5. 换一批：分页而不是重新随机

候选池里同一个字在一个位置上最多出现 1 次，所以首字天然最多 100 种，
再加上逐级放宽，完整排序有几百个。因此做法是**把完整排序交给界面做分页**：

- 生成时多留一个「候选带宽」（`max(top × 12, 240)`），一次枚举到底
- 点「换一批」只是从已排好的序列里切下一段，**不重新枚举**，所以是瞬时的
- 分页是确定性的：翻回去还是同一批，不同批次之间不重叠

实测默认参数下可翻 **20 批 / 240 个互不重复的候选**，
三批共 36 个名字的重叠数为 0。

之所以不做「随机种子 + 洗牌」：随机洗牌会把低分名字提前展示，
而分页是弱降序的 —— 第一批最好，越往后越差但是越不同。
对「挑名字」这个场景，后者更合理。

### 6. 同音替换：两层建议，两层可信度

导航需求是「喜欢这个读音，但嫌这个字被用滥了」。共 278 字的字库满足不了：
「书」在内层只能换出「符」。所以分两层：

| 层 | 来源 | 可靠度 | 能否算分 |
| --- | --- | --- | --- |
| 内层 | `CHAR_LIST` 字库 | 五行/康熙笔画/声调都是校验过的 | ✅ 分数可信 |
| 外层 | 联网同步的拼音表 | 读音可靠（公开数据集），五行与笔画**按部首推断**，释义来自新华字典 | ⚠️ 只能给参考分，界面标「*」 |

效果（已联网拼音表）：`书 → 舒（金·热度37）姝*（热度82）淑*（热度82）`，
每条都标出换成之后的总分变化。

**两条硬约束**：

1. **换字后若撞上新谐音，直接丢弃该候选** —— 读音变了就可能产生新谐音，
   宁可少给建议，也不能推荐一个坏名字。
2. **外层只推荐「重名热度表认得的字」**。这条是测出来的：
   不设门槛时拼音表里两万字全进来，实测把「饖」（异体字）
   和「鲭」（鱼名）推给了用户 —— 生僻字拿的是「默认热度」，
   看上去反而像「很冷门」，会被排到前面。踩过这个坑之后才加的过滤。

实测这个门槛只筛掉 **51 个字**，而它们全部是可用字：

```
轩 浩 宸 子 欣 嘉 怡 一 可 玥 诺 奕 语 妍 瑜 晨 硕 俊 雅 豪 洁 颖 琳 婷
翔 辉 丽 燕 艳 娟 芳 军 强 华 建 国 娜 莹 璇 璐 萌 柔 娴 淑 姝 蓝 青 翠 琦 哲 航
```

（这 51 个字也暴露了字库的一个不足：**它漏掉了当代最流行的一批起名用字**，
甚至包括「轩」「浩」「宸」「子」「欣」。想要它们，可以在「词库管理」里
用单字联网查询加入。）

### 7. 偏旁重复：只提示，不扣分

「李浅涵」三字全带氵、「李诗语」两字全带讠，念着不别扭但写出来笨重。
做法是一张**手工维护的偏旁分组表**（`web/js/data/radicals.js`，25 个分组）。

几个必须说清楚的点：

- **不是完整部首表**：只覆盖内置字库的 **228 / 278 字**。字库里另有 50 个字
  没有同族用字（如 文、方、平、白），强行归组只会造成误报，宁可不检测。
- **联网加入的字查不到**。正因为如此，它**只提示、不参与评分**：
  若拿它扣分，会让「联网加字」暗中拉低分数，属于数据缺陷污染排序。
  测试里有一条断言直接读 `score.js` 源码，确保它不引用 `Radical`。
- **歧义字按传统部首归组**：`梁`→木（不归氵）、`荣`→艹（不归木）、
  `寒`→宀（不归冫）、`霖`→雨（不归木）、`蕾`→艹（不归雨）。
  一个字不得同时属于两个分组，否则会误报（有断言死守）。
- 这张表是**对着真实字库导出后逐个核的**，不是凭空写的。
  当初就漏了字库的第一个字「梓」，测试里现在有一条
  「高频起名用字必须已归组」的断言专门守它。

## 手机上能用吗

能，但要看怎么打开。分两件事说清楚。

### 已经做到并实测过的

纯 HTML/CSS/JS，零外部依赖，没有任何框架或构建产物，所以**任何现代浏览器都能跑**。
用 320 / 360 / 390 px 三种手机宽度实测：

| 检查项 | 结果 |
| --- | --- |
| 横向撑破页面 | 无（文档宽 ≤ 视口宽） |
| 布局 | 自动收成单列（`.layout` 在 1000px 以下变一列） |
| 取名 / 词库管理 / 对比表 | 三个视图在 320px 下均无横向溢出 |
| 对比勾选框触控面积 | 103 × 44 px（原来只有 78 × 21，手指不好点，已改） |
| 出生时间 | 用原生 `datetime-local`，手机上直接唤出系统日期时间选择器 |

> 修这个时踩到一个坑：`.layout` 原本写的是 `grid-template-columns: 1fr`，
> 而 `1fr` 的最小值是 `auto` —— 对比表格的 `min-width: 460px` 会顺着 min-content
> 把网格轨道顶宽，390px 的手机上文档宽度变成 520px，页面被撑破。
> 正确写法是 `minmax(0, 1fr)`。这类「grid blowout」在桌面看不出来，只有窄屏才暴露。

### 还没验证、需要你实测的

**把单个 HTML 文件拷到手机上直接双击打开**这条路，各平台差异很大，我没有真机，
所以只能说清楚风险，不能替你打包票：

| 平台 | 直接开本地 HTML | 本地缓存（IndexedDB / localStorage） | 联网扩充词库 |
| --- | --- | --- | --- |
| Android Chrome | 一般可以（文件管理器 → 用 Chrome 打开） | `file://` 是不透明源，**可能被拒**，会降级到内存（刷新即丢） | 桌面实测可行，**手机未验证** |
| iOS Safari | 较麻烦，从「文件」App 打开本地 HTML 常不好使 | 同上 | 未验证 |

也就是说：**算八字、取名、看结果这些都能用**（纯本地计算，不依赖存储）；
但「联网扩充词库后缓存下来、下次还能用」这一条在 `file://` 下**可能失效** ——
代码里已经做了三级降级并在界面上提示，但真机行为得实测。

### 手机上最稳的用法

**不要用 `file://`，改成用 HTTP 打开。** 只要有个地址，上面那些限制全部消失：

```bash
# 电脑上起一个静态服务，手机连同一个 Wi-Fi 访问
npx serve dist/取名系统-完整版
# 或者
python -m http.server 8000 --directory dist/取名系统-完整版
```

然后手机浏览器打开 `http://<电脑局域网 IP>:端口/` 即可。

如果想让手机**离线也能用**，把 `dist/取名系统-完整版/` 丢到任意静态托管
（GitHub Pages、Netlify 等）也行 —— 它本来就是纯静态文件，
托管之后手机浏览器访问一次就会进缓存。

> 顺带一提：真要「联网查八字」，其实反而不需要 —— 见上文，
> 年月日时柱、节气、真太阳时都是本地精确计算的，不依赖任何接口。

1. **零外部引用**：一个请求加载完，没有相对路径问题（目录名是中文，避免任何编码意外）
2. **不会漏同步**：改完源码只要覆盖一个文件，不会出现「改了某个 js 但忘了拷进部署目录」
3. **HTTP 源下功能更全**：IndexedDB 与 CORS 都是正常行为，

- **方言数据默认关闭**：蜀拼表与四川方言词汇的来源仓库未声明授权，

## 已知局限

- **字库只有 278 字，而且漏掉了当代最流行的一批用字**：
  「轩」「浩」「宸」「子」「欣」「嘉」「怡」「玥」「诺」「奕」「语」「妍」
  这些热度 90+ 的爆款字都不在库里（它们出现在热度表里，却不在字库中）。
  直接后果是生成不出「李浩然」「李子涵」这类名字。
  补救办法：「词库管理」→ 单字联网查询 → 校正 → 入库。
- **偏旁表只覆盖字库的 228 / 278 字**，联网加的字查不到；
  且它不是正式部首表，是按「写出来像不像」手工分的组。
- **同音替换的外层字五行靠推断**，且只在「热度表认得的字」里推荐。
  代价是漏掉一些好用但没被热度表收录的字（例如「澍」）。
  外层建议的分数是参考值，**用之前请人工核对五行与笔画**。
- **四川话数据来自第三方个人项目且未声明授权**，所以默认不勾选、不进入分发包；
  个别读音与成都话实际有出入，因此四川话检测**只提示、不淘汰**。
  四川话内部分区差异也很大（成渝片 / 岷江片不同），无法一概而论。
- **小名是从大名衍生的**，不是独立生成；如果大名的用字都不适合做小名，
  给出的建议会标「有谐音风险」或分数偏低，需自行取舍。
- **城市经度取市中心点**（精度约 0.1° ≈ 24 秒时差），多数情况足够；
  若出生地离所选城市较远，请直接填经度。
- **重名热度是本地估算**，不是真实重名率。真实数据需要公安/运营商接口，
  浏览器端无法直连（跨域 + 需要授权）。界面里已明确标注。
- **康熙笔画与姓名学五行没有权威公开数据源**。内置字库是人工核定的，
  但联网加入的字只能按部首推断，界面上标为「推断」并要求人工核对。
- **繁→简是逐字转换**，覆盖靠联网的 OpenCC 表（4148 条）。
  内置兜底表较小，未收录的繁体字只会**漏匹配**、不会误转。
  另外 `乾`/`徵`/`藉`/`著`/`沈`/`甦`/`麼` 列入**保护名单不转换** ——
  因为「乾坤」「宫商角徵羽」在简体里本就保留这些字形，
  而 OpenCC 逐字表把「乾」的首选给了「干」，硬转会得到「干坤」这种错字。
  要彻底解决需要词组级规则，超出本项目范围。
- **联网后诗词出处命中率大幅上升**（35 首 → 850+ 首），
  代价是「有出处」这件事的区分度下降。内置的 35 首精选排在最前，会优先命中。
- **字库 278 字**，属于精选而非全字库。想要更多字，可以在「词库管理」里
  用单字联网查询逐个加入；也可以按
  `字|拼音|声调|五行|性别|风格|寓意|康熙笔画` 的格式往
  `web/js/data/chars.js` 的 `NS.RAW_CHARS` 里加。
- **只支持 BMP 内汉字**（基本区 + 扩展A + 兼容区）。
  扩展B 及以上需要代理对，与系统「一个汉字 = 一个码元」的处理方式冲突，故不收。
- **姓氏表 218 个**。不在表里的姓氏会依次退化到字库、联网词库取拼音笔画，
  再不行就提示手填笔画；此时谐音检测无法覆盖姓氏部分。
  （用联网字典查出的姓氏笔画是**简体笔画**，不是康熙笔画，界面会提示。）
- **存储可能降级**：优先 IndexedDB；不可用时退到 localStorage（约 5MB，
  字典可能放不下）；再不行只存内存（刷新即丢，界面会提示导出数据文件）。
- **三才五格属「数理派」**，与八字喜用神体系不同源，两者结论可能冲突。
  系统以八字为主、数理仅作参考。
- **节气算法误差 1–8 分钟**（低精度太阳位置公式的固有精度）。
  出生时间若紧贴节气，建议用专业软件复核。
- 未实现神煞、大运、流年等推算，也不做真太阳时的历史时区/夏令时还原。

## 旧版 Python 脚本

`naming_system.py` 是最初的实现（八字 + 字库 + 三才五格 + 诗词 + FastAPI 接口），
**保留作参考，网页版不依赖它**。原版有几个已在新版中修掉的问题：

1. 月柱天干公式错误 —— 原为 `(年干 × 2 + 月支) % 10`，
   正确的五虎遁是 `((年干 % 5) × 2 + 2 + 月支距寅的步数) % 10`。
   例如 2000-01-01 12:00 原版会算出「己卯 **甲子** 戊午 戊午」，
   正确是「己卯 **丙子** 戊午 戊午」。
2. 谐音用拼音子串匹配，大量误杀（见上文）。
3. 节气用固定日期近似表，边界可能差一天。
4. 三字名会因为组合爆炸而卡死。

想跑旧脚本需要 Python 3.10+（本机当前只有 Python 2.7）：

```bash
pip install -r requirements.txt
python naming_system.py                # 命令行演示
python naming_system.py --api          # 启动 FastAPI 服务
```
